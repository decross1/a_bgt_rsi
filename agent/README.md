# Agent-facing documentation

Root contracts and current task scope govern agent work. This directory holds
launch aids; it does not grant broader research, runtime, or Git authority.

## Reading order

1. the checkout-local `AGENTS.md` for Codex repository-maintenance authority, or
   [`../CLAUDE.md`](../CLAUDE.md) for Claude's operating contract.
2. [`../START_HERE.md`](../START_HERE.md) for current orientation and truth
   hierarchy.
3. [`../LOOP_V2.md`](../LOOP_V2.md) for v2 preparation and activation criteria.
4. [`../ARCHITECTURE.md`](../ARCHITECTURE.md) for the deployed system boundary.
5. The newest relevant [`../human/sessions/`](../human/sessions/) note and the
   explicit assignment for the session.

The v2 foundation retains the established serving runtime and research gates.
Use the canonical activation/deployment receipts to determine which campaign is
running. A controlled model study is separate from foundation adoption.

## Repository-maintenance authority

Direct Codex repository-management sessions use the standing authority in
the checkout-local `AGENTS.md`. Older “single commit authority” language applies
to the autonomous runtime and its bounded packet builders; it does not revoke a
direct Codex maintenance assignment.

A process launched by Nara or the packet dispatcher remains bound by its packet,
branch, tool, budget, and no-self-merge contract. A role label never widens that
runtime mandate.
