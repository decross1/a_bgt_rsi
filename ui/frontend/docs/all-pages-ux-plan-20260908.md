# Focused Lab page workflows

This frontend-only plan simplifies the existing Now, Operations, record library, experiment library, Channel, Calls and execution trace routes. The existing Research/Ladder canvas and its claim semantics are protected. No new page, backend change, scientific decision or runtime action is part of this change.

Baseline: public main8cf3e85a75167b22b31abf429c674268c46dcdfd. Success means one clear primary task per route, less duplicated default content, full evidence reachable through explicit disclosure, and preserved unknown/error/stale/identity/action semantics. Comparable screenshots and actual keyboard/narrow workflows must demonstrate that the existing task is easier to scan; a new summary above unchanged density fails.

Parallel work uses separate public-based worktrees and exact route-family ownership. One integrator owns App, global CSS, shared API/status/payload components, Operations and the existing FrontierReviews relocation. Dossier, Channel and trace builders start first; completed builders take evaluation, calls and Now as separately recorded disjoint allocations. Only the owner integrates reviewed commits.

1. Record before-state source/screenshots and missing workflow cases using inert private fixtures; preserve audit shortcomings rather than rerunning history.
2. Subtract duplicated panels and introduce concise selection/evidence flows within each existing route. Preserve deep links, aliases, full IDs, historical records and human confirmations.
3. Keep diagnostic outcome, authored summary, evidence validity and execution mode distinct. A dispatch ID permits an explicit lookup attempt, not an assumed call chain.
4. Integrate frontend-only slices, run focused regressions, then full frontend with --maxWorkers=2, sequential typecheck and build. No weakened assertions or real action endpoints.
5. Obtain fresh independent whole-source and screenshot/workflow review; preserve protected Research hashes and geometry. Resolve material findings within bounded correction allowances.
6. Publish a source-only PR and merge only qualified code. Verify adoption through the existing frontend process with served-source hashes and desktop/narrow flows; retain known-good source until qualified.

Each family has initial implementation plus two evidence-driven corrections. The owner pass has a three-hour source ceiling and four-hour terminal ceiling, with an hour reserved for review/delivery. Missing evidence or a repeated unexplained failure holds the affected slice; no scientific or service gate is bypassed. Partial delivery must identify the pending routes.
