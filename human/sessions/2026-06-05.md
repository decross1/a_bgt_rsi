### Scaling finding (feedback on the "~30 min active" goal)

Both workflows finished in **~10 min wall-clock** despite the 2nd having 14 agents (vs 7)
and harder per-agent work (VCG pivots, optimal-welfare search) — and 514k vs 334k tokens.
**Parallelism raised *active/compute* time (~1.5×) but not *wall-clock*:** wall-clock is the
critical path = build(parallel) + integrate(serial) + verify(parallel), each ~3-4 min, and
adding more *parallel* agents overlaps rather than extends it. To reach ~30 min *wall-clock*
of useful work the levers are: (a) **long real per-agent jobs** (a real n≥200 experiment run
is ~15 min in one agent — the n=2 smoke took 9.5s), (b) **more sequential phases** (deeper
dependency chains), or (c) **loop-until-dry** iterative passes. More parallel builders ≠
longer wall-clock. SDLC held at this scale because it was *encoded* (frozen contract +
spawn-contracts + validate gate + repro-check + 3-vote adversarial verify), not assumed.

### Findings the live test surfaced (the honest part)
The workflow's live smoke came back **BLOCKED for the right reason** (topic didn't escalate: weak
signal but 3 distinct books). So at the gate I validated the S2 integration directly:
- **S2 client works** against the real API (no crash, graceful, key auth) — broad keyword queries
  return the full 20 results with 4–11 abstracts each.
- **But real-world yield is low as-built**: a full-hypothesis query over-constrains S2's *keyword*
  relevance search (a 12-term query → **1 result**; a 4-term topic query → 20). I tried a positional
  keyword distillation (first-N content words) and **rejected it** — topical terms often trail a
  method/framing preamble, so it grabbed the framing (**0 results**). Robust query distillation is a
  genuine tuning problem (hard lexically without an LLM), documented as a KNOWN LIMITATION in
  `_distill_query` and left as a follow-up rather than over-engineered at the gate.
- **Plus**: the compound escalation trigger fires rarely (the GT-only corpus pulls ≥3 books for most
  topics), and S2 abstracts are frequently null (dropped by dedupe). So ML-Intern is **mechanically
  complete + safe + verified**, but its practical effectiveness is gated on (a) query distillation and
  (b) escalation-trigger calibration — both measurable follow-ups, neither blocking the seam closure.

The seam is closed (escalation now has a consumer that fetches + re-retrieves + degrades gracefully);
effectiveness tuning is the next increment.
