## The architectural finding — reference-passing

**The real issue:** Nara copies the full neighbors array (~1500
tokens) through every step's tool_call args. With vLLM's parsing
that's fine; with the inline text-content emission, it requires
~3000+ output tokens per turn just to serialize the call, which
doesn't fit in any reasonable per-turn cap.

**The fix (next session's first task):** reference-passing.
- Runtime maintains a per-iteration cache: `run_state/iteration_cache/<id>/retrieval.json`.
- `nara.py` writes captured results to the cache as they land.
- Tool schemas change for `novelty_classify` + `critic_loop_v0`:
  drop `neighbors` from required args; add `iteration_id`. Workers
  fetch from cache by id.
- Nara's prompt updated: "pass iteration_id, not neighbors."
- Tool_call payloads shrink from ~1500 tokens to ~50 tokens; the
  truncation issue disappears.
- Estimated effort: 60–90 min.
