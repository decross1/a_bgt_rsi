## Probe findings (durable — lifted out of the /tmp workflow output)

**Confidence metric.** A probability scalar in `[0,1]` — the human's
self-rated confidence in a free-text *prediction* typed BEFORE the verdict
form unlocks (the pre-verdict calibration capture, ARCH §6.5.4). UI: a
slider (`step 0.05`, default 0.50) with a 2-decimal readout. **STUBBED
end-to-end** — captured in component state, no durable writer (`gate_cli`
has no calibration subcommand; `/available.actions.calibration = False`; the
`calibration_entry` run-log writer + schema (Day 3.5) are unbuilt). Server
hard-rejects out-of-`[0,1]` with 422 (never coerced; rule 4).

**Finding review vs gate verdict.**
- *Gate verdict* = sign off the whole ITERATION (valid / needs_revision /
  invalid) via `gate_cli`, keyed `iteration_id`, → `loop_feedback.jsonl`.
  The Step-8 human gate.
- *Finding review* = adjudicate one surfaced CLAIM the iteration produced
  (validated / in_review / rejected) via `finding_session --set-status`,
  keyed `finding_id`, → `surfaced_findings.status.jsonl` (effective status =
  last audit row; the base file is never edited in place). validated/rejected
  ALSO dual-write a `loop_feedback` row against the finding's SOURCE
  iteration; in_review writes only the audit row and stays queued.
- Dashboard "N need you" = `gate_verdict + state_gate` only; `finding_review`
  is excluded (cockpit cargo, not the pipeline gate).
