### PART 1 — Dashboard reframe (BUILD NOW)

Reframe the dashboard **center into a system-overview snapshot** ("what's going
on right now"). This is **mostly a re-order + one coupling, NOT a rebuild** — the
pieces largely exist.

**Center vertical order (top → bottom):**
1. `HealthVerdict`
2. `SystemActivityHero`
3. `HealthStrip` **+ a NEW host-memory tile** (add host RAM/mem alongside the
   existing strip tiles)
4. `Vllm` panel / `Qwen` panel (keep BOTH side by side — do not remove or demote
   the Qwen health panel even though Qwen is currently unwired as a backend)

**The coupling (the load-bearing change).** **Couple the idle hero to the pending
human-todo count in EVERY state:** when idle, the hero reads

```
IDLE · N need you →
```

(`→` links to `/todo`). When not idle it shows live activity, but the pending
count remains coupled/visible. **N is the real-escalation count = taxonomy A + B
ONLY**, sourced from `/api/human_todo`:
- **A — judgment:** `gate_verdict` items.
- **B — blocking halt:** `state_gate` items.
- **NEVER count C:** `bubble_ack` (read-receipt) and `stale_active_run` (ops
  autopsy) are **not** decisions and must be excluded from N. (`needs_revision`
  has no actuator and is likewise excluded.)
The `/api/human_todo` backend already classifies these `kind`s
(`ui/backend/human_todo.py`); filter to `{gate_verdict, state_gate}` for N.

**REMOVE `HumanTodoPanel` from the dashboard.** It moves entirely to `/todo`.
This removal is **safe ONLY because of the coupling above** — the idle hero's
`N need you →` is now the dashboard's at-a-glance escalation signal, so nothing
silently sits pending off-screen (the failure the 2026-06-10 overhaul fixed). Do
**not** remove the panel without the coupling in place.

**REJECTED — do not build a slide-out drawer.** There is no such primitive in the
UI and one is not wanted. `<details>` disclosure + the dedicated `/todo` route are
sufficient; a net-new drawer is over-build (inviolate rule 8).

- **Gemma DEFENDS, Qwen ATTACKS** — D-044 independence: the interrogator must NOT
  be the authoring model. The human **directs** the topic and flow and may
  address either or both voices; this is **not** a spectator debate.

  (multi-turn, honest-defender, append-only transcript, turn/token caps,
  concurrency guard) — a PART-2 seam. Until it lands, render the chat pane as a
  stub.

**The 6 resolution forms** (the cockpit's outcome taxonomy — what a sign-off
RESULTS IN). Each is a form in `/todo`; `ui/backend` endpoints **exec the blessed
CLIs** (the UI never writes ledgers directly — it shells the writers-of-record per
D-046):
1. **Sign off** → verdict ledger + journal; Nara's next planning session proceeds.
   Sign-off MAY carry an optional **directive** ("proceed to <next step>") vs a
   bare "this is fine". (mostly exists)
2. **Reject** → invalid verdict; generator steers away / promotion blocks. (exists)
3. **Refine — defer to a session** → enqueue `dev_session_queue` via
   `todo_cli defer` (D-046); human writes code next session. (exists)
4. **Refine — authorize autonomous fix** → enqueue a **`spawn-contract`**; a coding
   agent later produces a BRANCH + tests + report that lands **only via the merge
   gate**. (NET-NEW, gated — PART-2 seam.)
5. **Spawn topic** → `finding_followups` queue. (exists)
6. **Abstain** → no verdict; honest exit; re-look later.

**`ui/backend` endpoints exec the blessed CLIs.** Each form posts to a thin
`ui/backend` endpoint that **shells the orchestrator CLI** for that outcome
(`gate_cli` / `todo_cli defer` / `finding_session --set-status` / followups; NEW
argv for the directive sign-off and the authorize-fix enqueue). The endpoint is a
shell-out, not a reimplementation.

**Pre-verdict calibration capture (ARCH §6.5.4).** **Before** the human records a
verdict, capture their **prediction + confidence**; persist as a calibration
entry (the `calibration_entry` run-log event per ARCH §6.5.4 / `research_program_v2`
red-flag). Calibration is captured *first*, then the verdict form opens.

**Tutor FENCED from the verdict.** Provide a tutor/explain affordance, but it is
**strictly separated from the verdict path** — no single agreeable model both
teaches and validates the same finding. The tutor cannot influence or auto-fill
the verdict.

**Concurrency warning.** The loop and the cockpit reuse the **same models**
(Gemma gen+defend; Qwen skeptic+attack). Real conflict is rare today (single-shot
loop + human-paced chat) but **show a warn/queue guard when an iteration is
mid-flight** (the model-health panels already surface contention; add the explicit
in-cockpit warning). Continuous-loop scheduling is a Phase-2 concern, not this
build.

**Autonomy / merge discipline (hard line on outcome 4).** UI approval authorizes
the **work**, not an unreviewed merge. Compliant shape: approve → enqueue
`spawn-contract` → coding agent → branch + tests + report →
